# 重开发架构蓝图

这份蓝图只记录重开发方向、系统架构和需要计算的指标，不展开代码实现细节。现有项目已经不只是 Backtrader 示例工程，真正要保留的是 `attbacktrader` 中形成的量化研究、A 股约束、回测证据和报告体系。

## 目标

重开发后的系统要成为一个面向 A 股的量化研究与组合回测平台。

这个项目的核心目的，是让回测策略变成可拔插的 Strategy Definition：换一套策略，只要它按统一证据契约输出信号、声明所需数据和指标，就能进入同一套数据准备、组合执行、交易约束、回测、归因和环境适配分析。

第一目标不是“写一个能跑的策略脚本”，而是形成一条可信证据链：

1. 数据准备清楚。
2. 指标计算清楚。
3. 策略信号清楚。
4. 交易约束清楚。
5. 组合回测清楚。
6. 归因报告清楚。
7. AI 只读证据，不制造证据。

最终要回答的问题不是“某一次回测赚没赚钱”，而是：

- 这个策略在哪些市场环境里更合适。
- 这个策略在哪些行业、波动、流动性、趋势结构里容易失效。
- 换一个策略后，是否仍能用同一套环境发现框架得到可比较的结论。

## 技术约束

### 一、只能使用数据驱动

- 所有策略判断必须来自已准备好的数据、指标快照、可交易状态和运行配置。
- 正式回测期间禁止联网补数据。
- 不能使用当前实时数据解释历史交易。
- 不能用报告层、AI 层或人工复盘后的结论反向制造策略信号。
- 所有入场、加仓、减仓、止盈、止损、拒绝、挂起、清仓都必须能追溯到当时可见的数据。

### 二、模块必须解耦

每个 Module 只通过稳定 Interface 协作，不能互相读取内部实现。

- 数据层只负责 Data Snapshot，不关心策略怎么用。
- 指标层只计算数值，不决定买卖。
- 策略层只输出 Trade Intent，不直接下单。
- 组合执行层只处理候选排序、资金、持仓容量和仓位约束。
- 约束层只判断交易是否可执行，不评价策略好坏。
- 回测引擎层只推进历史时间和成交事实，不创造策略信号。
- 报告层只消费 Run Artifact，不重跑策略、不重算信号、不补证据。
- AI 层只读证据和报告，不直接修改策略。

### 三、策略必须可拔插

任何策略接入平台时，都必须满足同一组规则：

- 声明策略名称和版本。
- 声明需要的数据范围。
- 声明需要计算的指标。
- 输出标准 Trade Intent。
- 输出稳定 reason code。
- 输出可归因的 signal values。
- 不直接访问 Tushare。
- 不直接读写报告。
- 不依赖某个回测引擎的内部对象。

只要满足这些规则，平台就应该能替换策略并复用：

- 数据准备。
- 指标计算。
- A 股交易约束。
- 组合回测。
- 交易生命周期。
- 环境发现。
- 报告与 AI 复盘。

### 四、只能通过配置驱动运行

- CLI 只能接收配置文件路径和少量非业务运行选项，例如 dry-run、日志级别、输出目录覆盖。
- 回测股范围、回测时间、买卖策略、通用组合规则、指标公式、归因内容都必须写在配置文件里。
- 禁止用 CLI 参数临时传入股票代码、起止日期、策略参数、指标公式或归因字段。
- 每次运行必须把解析后的配置固化为 Run Plan，并随 Run Artifact 一起保存。
- 同一个配置文件应能被复跑、比较和审计。

### 五、运行效率是架构约束

- 全 A 股、动态成分股和长周期回测都必须按批量数据处理设计，不能靠逐日逐股临时拼接。
- 回测前先解析 Backtest Stock Scope，生成每个交易日的 eligible symbols，正式回测期间直接读取。
- 指标必须优先复用本地指标快照；缺口补算也应按 symbol/timeframe/indicator 规划，不允许在策略判断时临时重算。
- Prepared Run Data 应按 Run Plan 缓存，多个策略或多个归因步骤复用同一批准备数据。
- 报告和归因只能消费已落盘的 Run Artifact 和宽表，不允许为了一个字段重新跑完整回测。
- 全部股票模式必须支持分片、并行、缓存和进度记录；失败股票要记录原因，不能拖垮整次运行。
- 性能优化不能破坏可复现性：并行顺序可以不同，Run Plan、交易事件和报告结果必须稳定。

## 总体架构

```text
配置层
  -> Run Plan
  -> 数据层
  -> 指标层
  -> 策略层
  -> 组合执行层
  -> 约束层
  -> 回测引擎层
  -> 归因与报告层
  -> AI 复盘层
```

策略是架构中的可替换模块，不是架构本身。当前接入的是 `Baoma V1`，后续可以替换为新的趋势策略、均值回归策略、行业轮动策略、低波动策略或其他策略。

### 数据层

职责：

- 管理本地离线 Data Snapshot。
- 接入 Tushare 等 Data Provider。
- 保存股票、指数、行业指数、行业分类、可交易状态。
- 保证正式回测只读本地快照，不临时联网补数据。
- 按配置解析 Backtest Stock Scope，而不是让策略自己决定股票范围。

核心原则：

- 数据准备和正式回测必须分开。
- 原始行情、可交易状态、行业数据、指标快照要分开保存。
- 每次回测必须能说明用了哪些快照。
- 回测股范围是配置，不是策略逻辑。

### 配置层

职责：

- 读取唯一配置文件。
- 校验配置完整性。
- 把配置解析为不可变 Run Plan。
- 固化本次运行的回测股范围、回测时间、策略、通用规则、指标公式和归因范围。

核心原则：

- 业务参数只能来自配置文件。
- 配置解析必须在回测开始前完成。
- 配置错误必须提前失败，不能进入半跑状态。
- Run Plan 一旦生成，正式回测期间不能再动态改变。

配置至少分成六个区域：

1. 回测股范围。
2. 回测时间。
3. 买卖策略。
4. 通用组合规则。
5. 指标计算公式。
6. 归因需要的内容。

#### 一、回测股范围

回测股范围是 Universe Selection 的配置输入，不属于某个策略。

支持的范围模式：

- 指定股票：直接列出要回测的股票代码。
- 固定成分股：从某个冻结日期的成分股清单回测，例如沪深300成分股、中证500成分股，或两者合并后的成分股清单。
- 动态成分股：按历史日期读取当时有效的指数成分股，也就是动态池。
- 全部股票：使用全 A 股作为候选范围，再由数据质量、可交易状态和策略规则筛选。

沪深300和中证500不是策略规则，也不是平台固定入口。它们只是“回测股范围”的一种配置方式：回测成分股。

动态池接入规则：

- 动态池必须来自本地 Time-Varying Stock Universe Manifest 或已准备好的成分股快照。
- 每个交易日先由动态池解析 eligible symbols，再交给策略判断。
- 动态池变化必须进入 Run Artifact，报告要能说明某只股票在哪些日期属于候选范围。
- 动态池不能在正式回测中实时查询当前成分股。

#### 二、回测时间

配置必须明确：

- 回测开始日期。
- 回测结束日期。
- 指标暖机数据范围。
- 交易统计开始日期。
- 是否允许期末强制清仓视图。

#### 三、买卖策略

配置必须明确：

- 策略名称和版本。
- 入场方法。
- 加仓方法。
- 止盈方法。
- 止损方法。
- 仓位方法。
- 每个方法需要的参数。

策略方法只能消费配置、数据和指标，不能从 CLI 或报告层拿运行时参数。

#### 四、通用组合规则

这些规则不属于某个策略，应作为平台通用规则配置：

- 最大持仓数量。
- 单票最大权重或最大市值。
- 单次买入比例。
- 现金使用规则。
- 同日卖出资金是否可用于买入。
- 是否优先买入当前未持仓行业的股票。
- 行业集中度上限。
- 候选排序规则。
- 交易成本、税费、滑点。

“是否需要持仓优先没有的行业”属于通用组合规则，不应写死在 Baoma V1 或任何单个策略里。

#### 五、指标计算公式

配置必须声明本次运行需要的指标和公式版本：

- KDJ。
- MACD。
- MA20、MA25、MA60。
- RSI14。
- ATR14。
- CCI14。
- BOLL_UP20_2。
- 未来新增指标的名称、参数、周期、版本和暖机要求。

指标公式一旦进入 Run Plan，正式回测期间不能变。

#### 六、归因需要的内容

配置必须声明本次需要哪些归因内容：

- 大盘环境。
- 行业环境。
- 个股入场结构。
- 波动率。
- 流动性。
- 市值与估值。
- 执行拒绝原因。
- 生命周期事件。
- 止盈、止损、加仓、减仓贡献。

归因字段只用于解释结果，不允许反向改变本次策略信号。

### 指标层

职责：

- 统一计算所有可复用指标。
- 为日线、周线、月线生成指标快照。
- 给策略、归因、报告和 AI 复盘提供同一份指标证据。

核心原则：

- 指标层只算数值，不做买卖判断。
- 暖机期不足时指标应缺失，不允许用 0、默认值或中性值填充。
- 策略不能自己重复计算通用指标。

### 策略层

职责：

- 定义策略模板。
- 绑定入场、止盈、止损、加仓、减仓、仓位规则。
- 输出 Trade Intent，而不是直接下单。
- 让不同策略在同一套 Interface 下接入回测系统。

核心原则：

- 策略只表达“为什么想买 / 卖 / 观望”。
- 策略必须记录信号证据，方便后续归因。
- 不能把回测后的归因结论直接塞回入场规则。
- 不能把 Baoma V1 的规则写死到平台主流程里。

### 组合执行层

职责：

- 根据同一天的候选信号排序。
- 处理现金、持仓数量、行业集中度、单票仓位、加仓和减仓。
- 形成组合层面的实际执行意图。

核心原则：

- 交易样本回测不是组合收益证据。
- 候选股票必须竞争现金和持仓容量。
- 同日卖出资金是否可复用必须作为明确规则披露。

### 约束层

职责：

- 模拟 A 股交易约束。
- 处理 T+1、涨跌停、停牌、整手交易、手续费、印花税、过户费、滑点、现金不足。

核心原则：

- 交易约束属于业务层，不应该藏在 Backtrader 默认行为里。
- 被约束拒绝的订单必须进入报告。
- 不能只报告成功交易。

### 回测引擎层

职责：

- 承接组合执行层和约束层的结果。
- 驱动历史时间前进。
- 生成成交、持仓、现金、净值、回撤等事实。

核心原则：

- Backtrader 是当前引擎实现，不是业务规则的归宿。
- 未来可以换引擎，但策略证据、交易约束和报告口径不应跟着重写。

### 归因与报告层

职责：

- 解释回测结果。
- 输出收益、风险、交易质量、执行成本、行业归因、市场环境、候选漏斗、生命周期复盘。
- 保存 Run Artifact，供人工和 AI 复盘。

核心原则：

- 报告只能消费已经存在的运行证据。
- 报告不能重新跑策略、重新抓数据、重新计算信号。
- 失败、拒绝、缺失、过滤都必须显式展示。

### AI 复盘层

职责：

- 读取已经固化的报告和样本证据。
- 帮助总结问题、提出实验候选、生成复盘意见。
- 解释策略适合的环境和不适合的环境。

核心原则：

- AI 不是证据来源。
- AI 不允许直接修改策略规则。
- AI 的结论必须能回指到 Run Artifact、Trade Lifecycle、Execution Audit 或 Review Packet。

## 当前回测策略：Baoma V1

`Baoma V1` 是当前已经接入并用于真实样本研究的回测策略。它是第一块策略模块，不是平台唯一策略。

### 策略定位

- 策略名称：`baoma_v1`。
- 当前接入模板：`trend_template_v1`。
- 当前研究目标：发现策略适合和不适合的环境。
- 当前证据口径：优先作为真实交易样本和环境发现，不直接当作最终组合收益证明。
- 当前常用回测股范围：沪深300 + 中证500 成分股固定池。这只是 Backtest Stock Scope 的一种配置，不是 Baoma V1 的策略规则。

### 入场规则

当前 Baoma 入场主要依赖：

- 价格站上 MA60。
- MACD DEA 最近上水。
- DEA 上水周期不超过指定交易日数。
- 前一交易日为阴线。
- 所需指标和前序交易日证据必须齐全。

入场信号只产生 Trade Intent。是否真正买入，还要经过组合执行层和 A 股交易约束层。

### 加仓规则

当前 Baoma 加仓复用入场结构，但额外要求：

- 当前已经持仓。
- 加仓次数没有超过上限。
- 当前交易生命周期没有曾经盈利。
- 仍满足价格、DEA、阴线等入场结构。

一旦当前生命周期曾经盈利或成本已被收回，后续不再允许加仓。

### 止损规则

当前 Baoma 止损依赖 MA60：

- 前一交易日跌破 MA60。
- 当前交易日收盘仍未收回 MA60。
- 满足后触发 Full Exit。

如果卖出因为停牌、跌停、T+1 等原因失败，退出意图不能取消，进入挂起清仓状态，后续只继续尝试清仓。

### 止盈规则

当前 Baoma 止盈依赖 MA25 和分批减仓：

- MA25 止盈：前一交易日跌破 MA25，当前交易日收盘仍未收回，并且当前剩余仓位处于盈利状态。
- 分批减仓：达到配置收益阈值后按阶段卖出部分仓位，卖出后重算剩余成本。
- 同一天 Full Exit 优先于分批减仓。

### 仓位与生命周期

当前 Baoma 回测关注交易生命周期：

- 入场。
- T+1 锁定。
- 可加仓持仓。
- 禁加仓持仓。
- 分批减仓。
- 离场观察。
- 清仓挂起。
- 已清仓。
- 期末未完成。

生命周期输出是报告、归因和 AI 复盘的权威证据来源。

### 环境发现目标

Baoma V1 当前最重要的输出，不是单次收益率，而是策略环境画像：

- 哪些大盘阶段更适合。
- 哪些行业环境更适合。
- 哪些个股入场结构更适合。
- 哪些波动和流动性环境更适合。
- 哪些执行约束导致收益受损。
- 哪些失败交易集中在同类环境里。

这个环境发现能力必须对所有策略复用。未来换策略后，仍然应该产出同一类环境适配结论。

## 需要计算的指标

### 一、基础行情字段

这些是所有计算的基础：

- 开盘价。
- 最高价。
- 最低价。
- 收盘价。
- 成交量。
- 成交额。
- 前复权价格口径。
- 交易日。
- 股票代码。
- 资产类型：股票、指数、行业指数。

### 二、可交易状态

用于判断真实可执行性：

- 是否停牌。
- 是否涨停。
- 是否跌停。
- 涨停价。
- 跌停价。
- 原始收盘价。
- ST 状态。
- 是否满足 A 股交易规则。

### 三、趋势与动量指标

当前系统已经支持或应优先保留：

- KDJ：K、D、J。
- MACD：DIF、DEA、MACD 柱。
- MA20。
- MA25。
- MA60。
- RSI14。
- CCI14。
- 布林线上轨：BOLL_UP20_2。

### 四、波动与风险指标

用于止损、加减仓、风险归因：

- ATR14。
- 单票波动率。
- 回撤。
- 最大回撤。
- 下行波动。
- 价格偏离均线程度。

### 五、流动性指标

用于过滤和容量判断：

- 成交额。
- 滚动成交额。
- 成交量。
- 换手或近似换手。
- 流动性排名。
- 成交不足告警。

### 六、市场环境指标

用于解释策略适配场景：

- 指数涨跌幅。
- 指数趋势。
- 指数回撤。
- 指数波动。
- 市场阶段。
- 行业扩散度。
- 行业指数强弱。
- 基准超额收益。

### 七、行业归因指标

用于解释收益来自哪里：

- 申万一级行业。
- 申万二级行业。
- 申万三级行业。
- 行业持仓贡献。
- 行业交易胜率。
- 行业收益贡献。
- 行业暴露集中度。

### 八、组合行为指标

用于判断策略是否像真实组合：

- 现金。
- 持仓数量。
- 持仓市值。
- 单票权重。
- 行业权重。
- 仓位暴露。
- 换手率。
- 订单数量。
- 成交数量。
- 拒绝数量。
- 成交率。
- 拒绝率。

### 九、交易质量指标

用于判断策略信号是否有效：

- 胜率。
- 盈亏比。
- 平均盈利。
- 平均亏损。
- 单笔净收益。
- 单笔毛收益。
- 持有天数。
- 入场后最大浮盈。
- 入场后最大浮亏。
- 止盈原因。
- 止损原因。
- 加仓贡献。
- 减仓贡献。

### 十、评分组合指标

用于后续 Scored Portfolio Backtest：

- 入场候选分数。
- 最低分数门槛。
- 候选排名。
- 被容量过滤数量。
- 被现金过滤数量。
- 被交易约束过滤数量。
- 被行业集中度过滤数量。
- 评分后实际成交数量。

## 推荐重开发顺序

### 第一阶段：固化架构与证据口径

- 保留 `attbacktrader` 作为业务框架。
- 保留 Backtrader 作为可替换回测引擎。
- 固化 Data Snapshot、Run Plan、Run Artifact、Trade Intent、Execution Audit、Backtest Report 的边界。
- 明确正式回测禁止联网。
- 固化“只能通过配置运行”的入口，CLI 不承载业务参数。
- 固化 Backtest Stock Scope 的四种模式：指定股票、固定成分股、动态成分股、全部股票。

### 第二阶段：先重做数据与指标

- 先把 Data Snapshot 和指标快照做好。
- 指标只算一次，策略和报告共用。
- 对 KDJ、MACD、MA、RSI、ATR、CCI、布林线上轨先建立稳定快照。
- 接入动态池所需的 Time-Varying Stock Universe Manifest。
- 为全 A 股和长周期回测建立分片、并行、缓存和失败记录机制。

### 第三阶段：重做组合执行

- 先做真实组合回测，不再把交易样本当组合收益。
- 候选股票必须排名并竞争持仓容量。
- 现金、持仓、拒绝原因和成本必须可追溯。
- 把“优先买入当前未持仓行业”等规则放入通用组合规则，而不是写进某个策略。

### 第四阶段：重做归因与 AI 复盘

- 报告层只读运行证据。
- AI 层只读报告和样本，不直接改策略。
- 每个 AI 结论必须能追溯到证据引用。
- 归因内容由配置决定；不同策略可以复用同一套环境适配报告。

## 不做的事

- 不做自动实盘交易。
- 不把 AI 结论当回测证据。
- 不在正式回测中联网补数据。
- 不把交易样本回测当组合收益。
- 不做全参数自动优化作为第一阶段目标。
- 不在 `backtrader/` 上堆业务规则，除非明确是在改回测引擎本身。
